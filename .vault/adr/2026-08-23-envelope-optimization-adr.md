# `envelope-optimization` adr: `Bounded return envelopes and the context budget ladder` | (**status:** `accepted`)

## Problem Statement

vaultspec-core's return surface has no budget. `2026-08-23-envelope-optimization-research`
measures the consequences: a single non-mutating command returns 416,754,257 bytes against a
10,476-document corpus, and the orientation call that opens every session costs roughly 75,000
tokens at the same scale. A decision is needed now rather than after the next feature, because
the unboundedness is not a set of isolated bugs to be fixed one at a time - it is a written
contract that says the machine surface is deliberately uncapped. Every command added under
that contract inherits the defect, so the contract has to change before the fixes mean
anything durable.

There is a second reason for deciding now. The regression guard that was supposed to hold the
static surface measured half of it, so the surface grew ungoverned for as long as the guard
has existed. Fixes without a corrected ratchet regress silently.

## Considerations

- The primary consumer of the machine surface is a model context window, not a script. The
  research records the contract that assumed otherwise.
- Two failure modes are independent: a payload that does not fit, and a payload that fits but
  displaces signal. Byte budgets catch only the first. The research measures information
  density as low as 15% on rows that are individually small.
- A larger context window does not solve either mode. It raises the bill for the same noise.
- Two defects are multipliers across the entire surface rather than properties of any one
  command: double serialisation on the MCP path and indent-2 on the CLI path. Fixing them once
  benefits every command; fixing commands first wastes the leverage.
- Quadratic enumeration is not an envelope defect and no envelope can mask it. The research
  measures 1,011,120 derived edges from 10,476 nodes in 20 minutes 16 seconds.
- Silent truncation is worse than overflow. Overflow fails loudly; a cut without a marker
  produces confident wrong answers.
- The elision machinery already exists and is correct - it is simply installed on the wrong
  side of the format branch, per the research's inventory of the five truncation constants.

## Considered options

**Raise the ceilings and rely on larger context windows.** Rejected. It addresses overflow and
ignores density, and the research measures payloads at 2,000 times a 200k window - no window
growth closes that gap.

**Cap each command individually as defects surface.** Rejected. It leaves the written contract
saying the machine surface is uncapped, so every new command reintroduces the defect, and it
forgoes the two surface-wide multipliers.

**Move bounding into the MCP gateway only.** Rejected. The gateway cannot bound 130 verbs it
does not own, and the CLI is called directly by agents as well as through the gateway, so the
defect would persist on the direct path.

**Return errors above a size threshold instead of truncating.** Rejected as the default. It
converts a saturation failure into a workflow failure, and the agent still cannot proceed. A
marked, paged truncation lets work continue. Retained as a fallback only where truncation
would produce a structurally invalid payload.

**Invert the contract: bound the payload, mark the elision, and derive the human render from
the same fields.** Chosen. It fixes the premise rather than its symptoms, and it makes the two
surfaces impossible to drift apart because both read the same bounded data.

## Constraints

- The double-serialisation multiplier lives in the vendored MCP SDK, which must not be edited -
  any reinstall reverts it. The SDK does provide a sanctioned escape: a caller-supplied result
  object is early-returned untouched, so the fix has to be made at this project's registration
  layer instead.
- Output schemas are generated by Pydantic from model docstrings. Reducing them means changing
  how schemas are generated, not editing prose, so the mechanism must be a schema-generation
  hook rather than a documentation edit.
- The bundled natural-language vaultspec content is out of scope for this decision. It is read
  to judge context cost but its wording is not changed here.
- Corrected measurement must land before any reduction, or gains cannot be held. This
  sequencing is a hard constraint, not a preference.
- The quadratic enumeration is a compute constraint before it is a payload constraint. Bounding
  the output alone leaves a command that does not return.

## Implementation

The decision has four parts.

**A budget ladder.** Orientation is capped at roughly 25,000 tokens for a large codebase, and
every tier derives from it: the static tool surface re-sent each turn is budgeted at 5,000
tokens; orientation at 6,000; discovery and listing at 4,000; a targeted single-document read
at 8,000; diagnostics at 4,000. No single response may exceed 10,000 tokens, roughly 35 KB, at
any scale. A realistic orientation sequence lands near 19,000 tokens, inside the ceiling with
headroom for the agent's own reasoning. Byte equivalents derive from the measured 3.46 bytes
per token recorded in the research.

**A boundedness contract.** A command is conformant only when it declares a default cap, a hard
ceiling the caller cannot raise, a total count so the caller knows what it did not see, and a
truncation marker. Missing any one of the four is non-conformant regardless of what the command
measures today. Boundedness is a property of the contract, not of the current corpus: a command
returning seven kilobytes with no cap is non-conformant, and the diagnostics command is exactly
that case, since its payload grows with how broken the vault is and is therefore largest when
the agent can least afford it.

**An information-density floor of 50%,** measured as useful bytes over wire bytes. Redundancy
counting against the floor: absolute path prefixes repeated per row, fields derivable from
other fields, null keys serialised anyway, values echoed back that the caller supplied, and
indentation whitespace. This dial is an engineering judgement rather than a derived quantity
and is expected to be re-tuned as the work proceeds.

**Elision moves into the payload.** The existing elision helper moves out of the render layer
and is applied before the format branch, so the envelope carries the elision as data and the
human renderer prints its summary line from those same fields. Two consequences follow
structurally: the two surfaces cannot drift, and a narrowing flag can never increase a payload,
because projection is selected before format.

Sequencing is fixed by leverage rather than severity. The corrected ratchet lands first. The
two surface-wide multipliers land next, because every later reduction is measured through them.
The contract inversion follows. The quadratic enumeration is then bounded at the algorithm,
streaming candidate pairs through a bounded per-node structure rather than materialising the
full pair set. Per-command envelopes follow in measured-byte order, and the static schema
surface last, since it is fixed cost rather than corpus-scaled.

## Rationale

The knockout criterion is that only this option changes the premise. The research shows the
uncapped machine surface is documented as intentional in three places; leaving that wording in
place while capping individual commands guarantees regression, because the next author reads
the contract, not the changelog.

The measured multipliers decide the sequencing. Double serialisation is a flat 2x on every MCP
tool and indent-2 is a flat quarter of every CLI payload, so both are worth more than any single
command fix and both are cheaper - one change at a registration boundary and one shared emitter.
Fixing commands first would mean measuring every subsequent gain through a doubling that a later
change removes anyway.

Density is included alongside size because size alone passes payloads that are almost entirely
noise. The research measures a row spending 298 wire bytes to convey 45, which no byte budget
flags and which degrades a model as surely as overflow does.

The quadratic case is separated from the envelope work because it is not the same kind of defect.
The research measures the command producing no output for fifteen minutes and completing only
after twenty; that is a compute failure that a response budget cannot reach, and treating it as
an envelope problem would produce a bounded response from a command that still cannot run.

## Consequences

The orientation and discovery paths become usable at corpus sizes the tool already claims to
support, and the improvement compounds: the multipliers apply beneath every per-command fix, so
later gains are larger than they appear in isolation.

The costs are real. Capping the machine surface breaks any existing consumer that relied on the
documented full dump; the truncation marker and total count make that breakage visible rather
than silent, but it is still breakage, and the diagnostics surface is where it will be felt
first. Bounding derived edges changes analytical output from exhaustive to ranked, which is a
genuine loss of completeness for any consumer that wanted every pair - the research finds no such
consumer, but absence of evidence is not proof.

Density work removes fields that are derivable rather than stored, which trades a small amount of
caller convenience for payload size and will require callers to derive what they previously read.
One field cannot be resolved from inside this repository: whether any host dereferences the
resource links that search rows carry. If one does, that field is retained and inlined bodies are
forbidden instead, which inverts part of the per-command remedy without disturbing this decision.

The ratchet changes the failure mode of future work. Tool-surface growth now fails a test rather
than passing unnoticed, which will surface as friction on unrelated changes. That friction is the
mechanism working, and the ceiling is written to be lowered as the work lands, never raised.
