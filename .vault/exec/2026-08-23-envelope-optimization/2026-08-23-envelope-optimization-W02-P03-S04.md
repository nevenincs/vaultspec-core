# Define the bounded envelope vocabulary carrying returned, total, truncated and next offset

## Scope

- `src/vaultspec_core/cli/rendering_shapes.py`

## Description

- Add a windowing module defining the bounded slice, the operation that applies it, and the
  human notice derived from it, so that cutting a collection and describing the cut are one
  operation rather than two a caller may perform separately.
- Give the shared multi-row emission point a limit, an offset and a row noun; apply the window
  before the format branch so both surfaces report the same numbers.
- Merge the window fields into the machine payload and derive the text notice from the same
  object, removing the possibility that the two surfaces disagree about what was withheld.
- Treat a non-positive limit as the default rather than as a slice bound.
- Retire the emission point's claim that its machine payload carries the full per-row set with
  no truncation.

## Outcome

This Step is infrastructure, not reduction, and its measurements are deliberately unchanged:
no surface adopts a default limit yet, so every payload is byte-identical to before. Measuring
it in bytes would measure the wrong property. What it establishes is that a cap can no longer
be added anywhere without its marker, because the operation that produces the rows also
produces the description.

The contract is five fields: how many rows came back, how many matched before the cut, whether
more follow, where to resume, and — when the window does not start at the beginning — where it
was positioned. The default window is fifty rows and the ceiling is five hundred, and the
ceiling cannot be raised from the request.

Verified by nine contract tests covering the ordinary case, the exhausted result, the final
page, a window positioned beyond the end, a negative limit, an oversized limit, and the
agreement between the two surfaces. The command and server suites pass at 1,718 tests. Lint,
formatting and type checking are clean.

## Notes

The vocabulary produced two instances of the defect it exists to prevent, both found by
enumerating edge cases before any caller adopted it.

The truncation marker was first defined as "fewer rows returned than matched". At a non-zero
offset that is wrong: a final page carrying the last ten of a larger result would report that
more followed when nothing did. It now means "more rows follow this window", which is the only
reading a caller can act on, and both descriptions were realigned to say so.

A window positioned past the end of a result reported no rows, the full total, and no
truncation, while omitting its own position. That is indistinguishable from a complete small
result — the misleading marker this work exists to remove, generated by the mechanism meant to
remove it. The position now travels whenever it is not at the start.

Neither defect was reachable from the intended path. Both the previous Step and this one
shipped an error that behaved correctly when exercised normally, which is now recorded as a
working assumption: this class of change is not verifiable by the happy path alone.

Closing a non-positive limit at the vocabulary level also resolves, for every future adopter,
the search tool's unbounded limit reaching a slice and returning nearly the whole result
instead of failing.

Two of the three passages specifying the machine surface as deliberately uncapped remain; they
belong to a later Step.
